# 操作手册

## 门店准备

管理员登录，系统参数先设置门店名称、货币（两位小数）及IANA时区。创建服务分类及项目，填写价格、时长、整理缓冲和是否必须占用房间/座位。已有预约后时区和货币锁定。

账号管理创建服务员工账号，角色选择“服务员工 / Stylist”；员工档案关联该账号、勾选可服务项目。员工与账号、服务及资源必须在同一门店。创建房间/座位并设置周排班，开始结束按门店本地时间（跨夏令时跳变的服务区间拒绝）；下班允许24:00，休息可留空。每员工每星期的一天只一段班次/一段休息。

请假/停用时段选员工或资源之一、开始和结束、原因。与已预约时段重叠会被拒绝，须先处理相应预约。不能用改排班悄悄使未来预约无效，也不能停用仍有未服务预约的员工/资源。

## 客户预约

顾客打开部署后的地址，注册客户账号（固定客户角色）、登录；也可由前台创建客户档案后代客预约。自助注册可后台关闭。姓名、联系方式和邮件同意可在个人资料修改，密码单独修改。

选择项目、员工、必需房间/座位及日期，查询可用时间后点击一个时段并提交。系统按15分钟开始点检查技能、排班、休息、请假、缓冲、员工/资源占用及本人撞期；选择后仍可能被其他人抢先预订，服务器会再次核验。最多预约未来90天，自助提前时间默认15分钟。

客户只看本人的预约，员工只看被分派给自己的预约，前台/店长按门店范围。无需让客户选择角色或录入别人的客户ID。

## 接待与服务

前台在日程按员工查看当日预约，也可切列表搜索/筛选/排序/分页。到店后记录“到店”，最早提前1小时、最迟结束后1小时。服务员工用自己的账号开始服务（最早提前15分钟）并在完成后填写服务记录。

管理员和前台不能冒名替员工完成服务；先在后台创建正确服务员工并重新分派（只允许到店或预约状态、接班员工仍需无撞期）。服务开始后不能取消、改期或换人。服务进行中持续占用，不因为计划结束就自动释放。

预约状态客户可改期/取消，默认至少提前60分钟；前台处理特殊情况需记录原因。改期保留原价格、时长和缓冲，不能借机换项目或变价。未到店必须等预约计划结束后，由前台记录原因，不自动制造违约费用。

## 结账与退款

服务完成进入待结账，由有结账权限的账号核价，折扣不能超过原价，有折扣须填原因。零价可直接完成；其他订单先核价再登记收款，可分笔现金、银行转账或外部支付。必须填实际凭据/参考号，金额不超过余额。

外部支付仅记录店员已确认的收款，不连接扫码网关、不扣银行卡。录错收款不能删历史：已结账原单选原付款条目，由有退款权限者填写退款金额、原因与凭据；每条原收款的累计退款不得超过该笔金额。

同一提交重试使用原requestKey，服务器指纹防双记；提示版本过期就刷新原单核对实际状态。不要用新请求键盲目重复付款。原单支持浏览器打印，内容只有业务资料。

## 报表、邮件及管理

报表的收款/退款按流水实际发生日、配置门店时区统计，净收款=收款−退款；完成服务金额与实际收款分列，未收余额为当前全部待收余额，不是选定日期内营业额。CSV同样只导出业务内容并防公式注入。预约尚未收款的金额不计收入。

邮件确认、改期、取消即时排队，预约在24小时以上则另排24小时前提醒。需客户邮件及同意、启用客户和账号、正确SMTP。NOT_CONFIGURED没有发出；SKIPPED表示无同意或无收件人；FAILED可在配置修复后重试；SENT只代表SMTP接受。旧修订任务取消。REMINDERS_ENABLED=false停止所有邮件调度。

管理员可管理账号、角色、菜单、部门、字典、参数与审计。最后一位有效全范围管理员不能被停用或移除核心权限。已关联员工或客户的账号身份不允许随意改角色/门店/用户名，密码和启停仍可管理；停用会撤销现有访问。内建客户角色不能提升权限，客户注册不能自选角色。

## 功能边界

已实现客户业务端和门店管理端，中文/英文响应式网页。没有原生App、套餐多项目联排、储值、会员次卡/积分、商品库存、供应链、提成工资、市场入驻、跨门店共用资源或税务发票。不支持医疗诊疗记录，也不是支付清算系统。邮件依赖外部SMTP；短信、WhatsApp和自动收款未实现。业务数据量超过每实体10,000条会拒绝列表请求，日历最多100条/日；需要扩容时应设计数据库分页并验收性能。
