# 架构与一致性

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 商业授权与定制开发微信：zhuatech / zhuatech2

浏览器Vue3 → 同源Nginx `/api` → Spring Boot / Spring Security → JPA / Flyway → MySQL8.4。SMTP工作任务由后端定时调度，不依赖在线支付或模型服务。

认证使用BCrypt成本12及服务端Session。浏览器仅保存界面语言，不保存密码或令牌。所有写操作（包括匿名注册）必须提供服务器CSRF令牌；API每次从数据库重新检查账号、角色和数据范围。CUSTOMER固定角色，STAFF可按角色ALL、DEPARTMENT、ASSIGNED控制。

BookingService处理容量、状态、核价及流水；SalonServiceManager处理档案、排班和停用；AdminService限制系统管理。CommandService哈希包含操作者、动作、目标与结构化输入，相同requestKey只接受完全相同请求。返回错误409需刷新原单，不能盲目用新键重复收款。

关键写事务先加部门1配置行锁，然后读取当前业务对象。Hikari明确使用READ_COMMITTED，避免MySQL默认一致性快照在等待锁后仍读取旧预约。单数据库部署可串行化容量和资金写入；此方式面向小门店，长时间SMTP发送也占用该锁，非大规模高并发设计。邮件每批最多20个、单连接5秒超时，失败延迟5分钟、最多3次。

预约冻结服务名称、价格、时长、缓冲、客户/员工/资源名称。服务变更不追溯旧预约。直接API输入也拒绝重复本地时间及跨夏令时跳变的服务区间。所有时间UTC存储并按配置IANA时区显示，创建/改期每15分钟一个开始点；缓冲参与占用。半开区间可首尾相接，服务中即使计划时长结束也继续占用，直至员工明确完成。已完成预约在原缓冲结束前仍占用。

支付为不可变账目，正金额、不超过剩余应收；退款必须关联本原单的原收款，每笔累积退款不超过原收款。原单修订号和幂等命令与流水同事务提交。折扣不超过原价；零价结账不添加虚假零额流水。外部支付方式是人工登记，不代表已对接网关或自动核实付款。

邮件队列事务持久化，按当前预约修订号取消旧任务，检查联系人启用及邮件同意。不配置SMTP不会假装发出。SMTP网络存在“已接受但连接中断”的不确定结果，重试可能重复，不能宣称恰好一次或送达/阅读回执。通知正文只有业务内容。

Store限制实体列表最多10,000条，内存范围过滤与分页适合学习和小规模验证；业务量增大需改为数据库范围查询、分页、独立通知锁和监测。没有多租户隔离保证或跨门店共享资源。
